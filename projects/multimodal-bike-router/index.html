Multimodal Route Planner

A schedule-aware bicycle-to-bus prototype for making first-/last-mile tradeoffs explicit—not just returning the fastest path.

Los Angeles direct-bus prototype

A better question than “what is the fastest route?”

First- and last-mile access can determine whether transit is practical, yet a fastest-path result often hides the bicycle conditions required to reach the bus. This project combines scheduled transit feasibility with bicycle-network routing to return two usable itineraries: Fast, which minimizes final arrival time, and Safe, which prioritizes lower risk-weighted bicycle exposure while staying within a configurable arrival-time budget.

The result is a compact decision tool for comparing the time, waiting, transfer points, and cycling-infrastructure implications of a complete trip.

Prototype scope

Bicycle access + one scheduled, directionally feasible direct bus trip + bicycle egress.

Built as experimental planning software, not turn-by-turn navigation or safety advice.

Place

Los Angeles, using local bikeway data and LA Metro/LADOT GTFS snapshots.

Decision

Compare earliest arrival against a safer bicycle-access alternative.

Routing engine

OSMnx + NetworkX weighted graphs, GeoPandas, Shapely, and Pandas.

Interface

Python API, reproducible notebook, static figures, and a local Streamlit demo.

Worked example

North Hollywood to UCLA: the same bus, two different bicycle experiences

For a requested 8:00 AM departure on June 24, 2026, the planner found two viable itineraries using LA Metro bus 761. The Safe option arrived only 6.5 minutes later than Fast, but substantially changed the bicycle portion of the trip: it more than doubled Class I/IV coverage and reduced the configured exposure score by over half for just 0.09 additional bicycle miles.

Method

Schedule feasibility meets street-level tradeoffs

01

Find reachable stops

Geocode the endpoints, identify stops within configurable bicycle radii, and construct access and egress bicycle graphs from OpenStreetMap.

02

Respect the timetable

Search GTFS calendars, exceptions, stop times, boarding rules, direction, and a boarding buffer to find scheduled direct-bus trips that can actually be reached.

03

Score bicycle links

Overlay City of Los Angeles bikeway classes and residential-street tags onto network edges, then assign configurable routing costs to each link.

04

Return a meaningful pair

Select Fast by final arrival time; select Safe by lowest bicycle exposure among alternatives that arrive within the allowed delay—10 minutes by default.

What the comparison reveals

The “safer” route is not simply a longer route

Both returned itineraries have almost identical bicycle mileage. The difference is where that mileage occurs: the Safe option shifts distance toward protected infrastructure and residential streets, changing the exposure profile without demanding a large detour. The time chart also makes clear whether the added minutes come from cycling, waiting, transit travel, or egress.

Responsible scope

Designed to be inspectable, not overconfident

The v0.1 prototype intentionally focuses on a narrow, auditable problem. It uses point-in-time data snapshots for reproducibility and separates code licensing from source-data terms and attribution.

  • No transfers, rail, walking legs, bike share, fares, accessibility constraints, or real-time arrivals.
  • “Safe” represents adjustable infrastructure and residential-street preferences, not a guarantee of safety.
  • GTFS refreshes are explicit and reviewable; route requests do not silently change local transit data.
